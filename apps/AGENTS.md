# AGENTS.md — `apps/` (frontend)

The root `AGENTS.md` governs this tree; this file is the frontend delta for
`apps/web` and its contract with `packages/ui`. Backend rules live in
`apps/api/AGENTS.md`.

## Stack

```text
apps/web      TanStack Start (SSR) + TanStack Router (file routes) + React 19
              Tailwind v4 (@tailwindcss/vite) for every style; no CSS modules
packages/ui   Base UI primitives, design tokens, and the stylesheet
```

Adopt another framework, state layer, or data library (TanStack Query, a
form library) only when it removes concrete complexity from accepted
product behavior, and record the decision in `docs/decisions/`.

## Filesystem

Create directories only when real files justify them.

```text
apps/web/
├── src/
│   ├── routes/            # URL topology; one file per navigable surface
│   │   └── __root.tsx     # document shell, head, not-found page
│   ├── features/          # concrete product concepts (page-frame)
│   ├── dev-annotations.tsx # Agentation toolbar, development only
│   ├── router.tsx
│   ├── app.css            # the one global stylesheet
│   └── routeTree.gen.ts   # generated by the router plugin; never edit
└── test/build/            # bun tests against dist/ (the production build)
```

A route exists because a person needs a durable, navigable surface. A
feature folder exists because a product concept does. Routes compose
features; features never import each other (oxlint enforces it). A frame that hosts
another feature takes it as `children` (`PageFrame` receives the
page content from `routes/index.tsx`); what two features share
moves to the narrowest common owner.

Imports across folders go through the package alias `#features/*`; never two
levels up. The first API call adds `src/api/client.ts` and its `#api/*` alias
(`docs/playbooks/add-api-feature.md`).

## Styling

- Style with Tailwind classes in the component. A `@nomi/ui` primitive takes
  `className` for layout only (margin, width); its color, type and states
  come from its variant props.
- Color comes from roles only: `bg-page`, `text-secondary-foreground`,
  `border-border-subtle`, `bg-brand-solid`. Never a scale step (`--brand-9`),
  a hex or oklch value, an arbitrary color (`bg-[#...]`), or Tailwind's own
  palette (it is removed). Type comes from `text-heading-*`, `text-body-*`,
  `text-caption-*`, `text-code-*`; radius and shadow from the theme
  (`rounded-lg`, `shadow-default`).
- Light and dark are the roles themselves flipping, so app code never uses a
  `dark:` variant or branches on color scheme. The theme classes (`light`,
  `dark`) belong on `<html>` only; `features/theme` owns them.
- Repeated geometry belongs in a component class in
  `packages/ui/src/styles/components.css`; one-off layout stays inline.
- Global CSS is limited to `app.css`, which imports `@nomi/ui/styles.css`.

## Data

- The browser calls the API at its own origin under `/api` (through the typed
  client and the dev proxy, both added with the first API call); the
  production reverse proxy forwards it to `apps/api`. Never hard-code an API
  host.
- Wrap each API call in a feature function that returns what the person
  should see, not an HTTP response, so components never interpret HTTP status
  codes.
- Never present more than the server confirmed: UI state for work the API
  does elsewhere comes from the status the API reports.
- Server failures surface at the field they concern (Base UI `Form` `errors`)
  or as one sentence near the action, never as a raw message.

## Accessibility

Every control has a visible or programmatic label, every page one `h1`, and
sections are labelled by their headings. Use Base UI's composition (`Field`,
`Form`) rather than re-implementing labelling or validation.
