# AGENTS.md — `apps/` (frontend)

The root `AGENTS.md` governs this tree; this file is the frontend delta for
`apps/web` and its contract with `packages/ui`. Backend rules live in
`apps/api/AGENTS.md`.

## Stack

```text
apps/web      TanStack Start (SSR) + TanStack Router (file routes) + React 19
              StyleX for every style; no Tailwind, no CSS modules
packages/ui   Base UI primitives styled with StyleX tokens
```

Design libraries (`docs/decisions/0007-base-ui-design-kit.md`):

```text
motion             presence (AnimatePresence), springs, gestures, layout;
                   simple state transitions (hover, press) stay CSS
blode-icons-react  icons: `import { SearchIcon } from "blode-icons-react"`
@blobatar/react    avatars for anyone without a picture: <Blobatar name=... />
dialkit            useDialKit(...) exposes values to the dev panel for tuning
agentation         dev-only annotation toolbar (src/dev-tools.tsx)
```

Adopt another framework, state layer, or data library (TanStack Query, a
form library) only when it removes concrete complexity from accepted
product behavior, and record the decision in `docs/decisions/`.

## Filesystem

Create directories only when real files justify them.

```text
apps/web/
├── src/
│   ├── routes/            # URL topology; one file per navigable surface
│   │   └── __root.tsx     # document shell, head, not-found page
│   ├── features/          # concrete product concepts (kit: the design kit page)
│   ├── api/client.ts      # the one typed boundary to apps/api (Eden)
│   ├── dev-tools.tsx      # Agentation + DialKit panels, development only
│   ├── router.tsx
│   ├── app.css            # the one global stylesheet
│   └── routeTree.gen.ts   # generated by the router plugin; never edit
└── test/build/            # bun tests against dist/ (the production build)
```

A route exists because a person needs a durable, navigable surface. A
feature folder exists because a product concept does. Routes compose
features; features never import each other (oxlint enforces it). A frame that hosts
another feature takes it as `children` from the route; what two features
share moves to the narrowest common owner.

Imports across folders go through the package aliases (`#api/*`,
`#features/*`); never two levels up.

## Styling

- Style with `stylex.create` beside the component. Pass styles down through a
  component's `xstyle` prop; `@ouro/ui` primitives take no `className` or
  `style`.
- Read values from `@ouro/ui/tokens.stylex` (`color`, `space`, `fontSize`,
  `radius`, `media`, ...). No raw hex, rgb, or pixel spacing in app code.
- Brand: headings and the wordmark use `font.heading` (EB Garamond) with
  `tracking.heading`; body and UI text stay Glide; code is Glide Mono. Brand color comes from
  roles (`color.brandSurface`, `brandText`, ...); `primary` stays neutral.
- Responsive and state values are conditions on the property
  (`{ default: ..., [media.sm]: ... }`), not separate rules.
- Light and dark follow the system preference through the tokens; app code
  never branches on color scheme.
- Global CSS is limited to `app.css`, which imports `@ouro/ui/base.css`.

## Data

- The browser calls the API at its own origin under `/api`
  (`src/api/client.ts`); the dev server and the production proxy forward it to
  `apps/api`. Never hard-code an API host.
- Wrap each API call in a feature function that returns what the person
  should see (`startReview` → `StartOutcome`), so components never
  interpret HTTP status codes.
- Never present more than the server confirmed: UI state for an external
  process comes from the status the API reports.
- Server failures surface at the field they concern (Base UI `Form` `errors`)
  or as one sentence near the action, never as a raw message.

## Accessibility

Every control has a visible or programmatic label, every page one `h1`, and
sections are labelled by their headings. Use Base UI's composition (`Field`,
`Form`) rather than re-implementing labelling or validation.
